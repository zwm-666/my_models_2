# CAPT-UniShape 实验思路、模型设计与数据处理方案

本文实验围绕质子交换膜燃料电池（PEMFC）故障识别任务展开，目标是在不同训练样本比例、不同模型结构和不同噪声扰动条件下，验证 CAPT-UniShape 模型对电堆运行状态、阻抗统计信息和工况变量的联合建模能力。整体思路不是单纯追求单一划分下的最优精度，而是从泛化能力、模块有效性和鲁棒性三个层面系统评价模型：首先通过四组训练集/测试集比例验证模型在样本量变化下的稳定性；其次通过消融实验分析 UniShape 表征、Residual KAN-Fusion、工况感知动态原型和多源输入对性能的贡献；最后在干净训练、噪声测试的设置下评估模型面对传感器扰动时的抗干扰能力。

## 1. 实验总体思路

实验设计保留三条主线。第一条为固定验证/测试集下的训练样本比例递减实验。具体而言，先按 8:2 协议生成一套固定的验证集和测试集，然后在同一个训练池内按 8:2、7:3、6:4 和 5:5 对应的训练数据规模进行分层子采样。这样四个比例面对的是同一套验证/测试样本，测试集难度保持一致，可避免“训练比例越低但测试集越容易”造成的反常结论。对比模型包括逻辑回归、支持向量机、随机森林、MLP、1D-CNN、LSTM、Transformer 和 iTransformer。该实验用于回答“在测试分布固定时，CAPT-UniShape 对训练数据减少是否仍具有稳定性”。若需要分析不同 held-out 比例本身带来的分布迁移，可将独立比例划分作为补充实验，而不作为主表结论。

第二条为模型消融实验，固定主要数据划分和训练协议，逐项移除或替换关键模块，包括去除 RBF 动态原型头、关闭 Residual KAN-Fusion、关闭工况感知 prototype transport、移除原型迁移正则、移除原型分离正则、置零 EIS 输入、置零工况输入、仅保留电堆运行分支以及仅保留 EIS/工况分支。该实验用于说明模型性能不是由单一大参数模型带来的，而是来源于多源表征、非线性融合和工况感知分类头之间的协同作用。

第三条为噪声鲁棒性实验。模型在干净训练集上训练完成后，只在测试集输入中加入不同强度的相对高斯噪声，噪声标准差设置为 0、0.01、0.03、0.05 和 0.10，默认同时作用于电堆运行序列、EIS 构造序列和工况向量。该实验用于模拟实际采集过程中传感器波动、阻抗统计误差和工况记录偏差对故障识别结果的影响。

所有深度模型训练均采用 AdamW 优化器和早停机制，早停指标为验证集 Macro-F1。验证集用于选择最佳 epoch，默认不将 train 与 validation 合并重训最终模型，从而保持验证集与测试集之间的独立性。论文主表优先报告测试集 Accuracy、Macro-F1、单样本推理时间和参数量，并结合混淆矩阵分析各类别识别差异。

## 2. 数据处理与样本构建设计

原始数据来自 `data/raw/测试数据.xlsx`，其中包含测试时间、故障类别、电堆总电压、电堆总电流、电堆功率、阻抗/EIS 统计特征以及可选的单片电压信息。为了与当前真实论文实验保持一致，主实验默认采用 `stack` 输入方案，即电堆总电压、电堆总电流和电堆功率构成运行序列 `x_op`；9 个阻抗/EIS 统计量与 3 个电堆变量共同构成工况向量 `x_cond`；同时由 9 个阻抗/EIS 统计量构造 4 通道 EIS 形状序列 `x_eis`。最终模型输入保存为统一的 NPZ 格式：

```text
x_op   = [N, C_op, T]，电堆运行时间序列，当前主实验 C_op=3，T=64
x_eis  = [N, 4, F]，由阻抗统计量构造的 EIS 形状序列，F=128
x_cond = [N, 12]，9 个阻抗/EIS 统计量 + 3 个电堆变量
labels = [N]，故障类别标签
split  = [N]，0/1/2 分别表示训练集、验证集和测试集
```

数据划分采用基于连续工况片段的分组分层策略，而不是对全部窗口样本随机打散。具体而言，首先按测试时间排序，当相邻记录时间间隔超过阈值或故障标签发生变化时开启新的 segment；随后将较长连续片段进一步切分为固定时长 block，当前主实验默认使用 240 秒块。这样可以避免同一连续工况片段被同时分配到训练集和测试集，也可以防止滑动窗口跨越故障类别边界，从而降低数据泄漏风险。

在得到 segment/block 级别的分组后，按照故障类别进行分层抽样。针对验证集与测试集差异过大的问题，改进后的主实验优先采用 `holdout_first` 策略：先在 group/block 级别划分训练集与 held-out 集合，再从 held-out 集合中按类别分层划出验证集和测试集。这样验证集和测试集来自同一个外部保留池，而不是让验证集从训练候选集内部产生，可降低验证集相对训练集过近、测试集相对训练集过远导致的选模偏差。验证集比例仍沿用原协议中“训练候选集内部比例”的语义，因此在 8:2 设置且 `val_size=0.25` 时，实际约为 60% 训练、20% 验证和 20% 测试。为复现实验历史，代码仍保留 `two_stage` 选项；为诊断不同划分难度，也保留直接三路划分 `three_way` 选项。所有归一化统计量只在训练组上计算，然后应用到训练、验证和测试样本，以保证测试集信息不会提前泄漏到预处理过程。

样本构建采用滑动窗口方法。对每个分组内的连续记录，按窗口长度 `window_size=64` 截取电堆运行序列；训练集步长默认为 16，验证集和测试集步长默认为 64。训练集采用较小步长是为了增加可学习窗口数量，验证/测试集采用较大步长是为了减少高度重叠样本对评价结果的影响。若某一分组长度短于窗口长度，则使用边缘值复制进行补齐，保证所有样本具有统一输入形状。

EIS 输入不是直接使用原始完整频谱，而是根据当前数据中已有的 9 个阻抗/EIS 统计量构造研究可用的形状序列。具体做法是先将 9 个统计量视为有序阻抗统计曲线，在归一化频率坐标上插值到长度为 128 的序列；随后构造一阶差分、中心化累计形状以及归一化频率坐标，共同形成 4 个通道。该设计使模型能够从有限的阻抗统计信息中提取近似的谱形变化、局部变化趋势和整体累积形态。后续若获得原始全频 EIS 谱，可在保持 `x_eis` 键和模型接口不变的前提下，将该构造序列替换为真实频谱通道。

早期曾尝试训练集类别感知滑窗步长，即少数类使用更密步长、多数类使用更稀步长，以缓解类别不均衡问题。但该策略会改变训练窗口分布，尤其可能减少多数类连续片段覆盖，导致测试集泛化下降。因此当前主实验默认不启用类别感知滑窗补偿，只将其保留为可选对照项。主实验采用更稳健的分段划分、更大的验证集和多比例测试来体现模型在真实分布下的泛化能力。

## 3. CAPT-UniShape 模型设计

CAPT-UniShape 的核心思想是在 UniShape 时间序列形状表征基础上，引入多源输入融合和工况感知动态原型分类机制。PEMFC 故障并非只体现为某个单一传感器的数值异常，而往往同时表现为电堆运行曲线变化、阻抗统计形态变化和工况条件变化。因此，模型将电堆运行序列、EIS 构造序列和工况向量分别编码，再通过非线性融合模块形成统一故障表征，最后使用随工况自适应迁移的类别原型完成分类。

模型包含四个主要部分：双分支 UniShape 特征提取器、工况编码器、Residual KAN-Fusion 融合模块和工况感知 RBF 动态原型头。对于电堆运行输入 `x_op` 和 EIS 输入 `x_eis`，模型分别使用官方 UniShape backbone 进行特征提取。UniShape 原本面向单变量时间序列，当前实现对多通道输入采用共享单变量编码器逐通道提取特征，再通过通道注意力聚合得到分支级表示。这样既保留 UniShape 对局部形状和多尺度时间模式的建模能力，又能适配多通道 PEMFC 数据。

对于工况输入 `x_cond`，模型使用由全连接层、LayerNorm、GELU 和 Dropout 构成的 MLP 编码器，将 12 维工况/阻抗统计向量映射到与 UniShape 输出一致的 `d_model` 维空间。该工况表示一方面作为融合输入参与全局故障表征构建，另一方面作为动态原型迁移的条件变量，使分类边界能够随工作条件发生适度调整。

融合阶段将三个分支表示拼接为 `[z_op, z_eis, z_cond]`，再输入 Residual KAN-Fusion 模块。该模块包含一条稳定的 MLP 主分支和一条 KAN 非线性残差分支：主分支负责学习基础融合表示，KAN 分支先将高维拼接特征压缩到瓶颈空间，再通过基函数层建模复杂非线性关系，最后以可学习权重残差叠加到主分支输出。其形式可概括为：

```text
h = MLP([z_op, z_eis, z_cond]) + λ · Linear(KAN(Bottleneck([z_op, z_eis, z_cond])))
```

这种设计避免 KAN 直接处理过高维输入带来的不稳定，同时利用 KAN 对非线性函数关系的表达能力增强多源特征融合。

分类阶段采用 Condition-Aware Prototype Transport，即工况感知原型迁移。模型为每个故障类别维护一个静态类别原型，并使用 RBF 条件映射器根据当前样本的工况表示生成类别级原型偏移量。对于第 `k` 类，动态原型可表示为静态原型与工况相关偏移的和：

```text
p_k(x_cond) = p_k + Δp_k(z_cond)
```

其中 `Δp_k(z_cond)` 由 RBF 基函数映射得到。随后将融合表示 `h` 与各类别动态原型进行归一化余弦相似度计算，并通过温度系数缩放得到分类 logits。与普通线性分类器相比，动态原型头能够表达“同一故障类别在不同工况下具有相近但不完全相同的表征中心”这一物理事实，从而提高跨工况识别能力。

考虑到 PEMFC 故障数据存在类别不均衡，主实验在交叉熵项中引入基于训练集样本数的温和类别权重。为避免直接逆频率权重在小样本少数类上造成过强梯度，默认采用 `sqrt_balanced`，即先计算逆频率权重再取平方根，并归一化到平均权重约为 1。这样可以在不改变原始样本分布的情况下提高少数类样本对梯度更新的贡献，同时降低强加权导致多数类判别边界被破坏的风险。训练损失由类别加权交叉熵损失、原型迁移幅值正则、原型分离正则和 KAN 正则共同构成：

```text
L = L_wce + α_transport L_transport + α_sep L_sep + α_kan L_kan
```

其中，`L_wce` 为类别加权交叉熵，`L_transport` 约束动态原型偏移幅度，防止工况迁移过大导致类别语义漂移；`L_sep` 约束静态类别原型之间保持足够间隔，降低类别混淆；`L_kan` 用于抑制 KAN 分支过拟合。当前主实验配置中 `d_model=128`，RBF 中心数为 16，温度初值为 0.07，`α_transport=0.001`，`α_sep=0.001`，`α_kan=0.0001`。若类别加权交叉熵仍不能充分改善少数类召回率，可进一步将 Focal Loss 作为可选对照，而不建议直接替代主实验损失。

## 4. 对比模型与消融设计

为保证实验结论具有说服力，基准对比覆盖从传统机器学习到序列深度模型的多类方法。传统机器学习模型将 `x_op`、`x_eis` 和 `x_cond` 展平后输入分类器，包括逻辑回归、SVM 和随机森林；常规深度学习模型包括 MLP、1D-CNN 和 LSTM；Transformer 类模型包括标准 Transformer 和 iTransformer。所有模型使用相同的数据划分和相同的测试集评价指标，避免由于数据划分不同造成不公平比较。

消融实验围绕 CAPT-UniShape 的关键假设展开。`no_rbf` 用普通 MLP 分类头替换动态原型头，用于验证工况感知原型分类的贡献；`no_kan_fusion` 去除 KAN 残差分支，用于验证非线性融合模块的贡献；`static_prototype` 保留原型分类但关闭工况迁移，用于区分“原型分类”与“工况感知动态原型”的影响；`no_transport_reg` 和 `no_separation_reg` 分别去除原型迁移幅值约束和类别原型分离约束，用于分析正则项对稳定训练和类别可分性的作用；`no_eis_input`、`no_condition_input`、`stack_only` 和 `eis_cond_only` 则从输入层面分析电堆运行序列、EIS 统计形态和工况变量各自的贡献。

在改进优先级上，本文将类别加权交叉熵和三路分组分层抽样作为 P0 项，因为二者分别对应优化目标与类别不平衡的匹配问题、以及验证/测试划分在少数类工况覆盖上的稳定性问题；将融合策略对比、逐类 F1 与归一化混淆矩阵作为 P1 项。融合策略对比至少应保留完整 Residual KAN-Fusion 与 `no_kan_fusion` 的 MLP 融合对照，以证明 KAN 残差分支的必要性；若篇幅允许，可进一步补充不同融合形式的额外对照。

## 5. 结果分析建议

论文结果建议围绕四个问题展开。第一，CAPT-UniShape 在四种训练/测试比例下是否整体优于传统机器学习、常规深度模型和 Transformer 类模型，尤其关注训练比例下降时 Macro-F1 的保持能力。第二，消融实验中完整模型相对于 `no_rbf`、`static_prototype` 和 `no_kan_fusion` 是否具有稳定增益，从而证明动态原型迁移和 KAN 融合不是冗余模块。第三，置零 EIS 或工况输入后性能是否下降，用于说明阻抗统计信息与工况信息对 PEMFC 故障分类具有补充价值。第四，在噪声强度逐渐增大时，CAPT-UniShape 的 Accuracy 和 Macro-F1 是否下降更缓，是否优于无 RBF 动态原型的内部对照模型。

最终论文表格建议包含 Accuracy、Macro-F1、Weighted-F1、参数量和单样本推理时间；补充表或附录需给出每个类别的 Precision、Recall、F1 和 Support。图形建议包括四比例基准对比柱状图、消融实验结果图、噪声强度—性能曲线以及按真实类别行归一化的测试集混淆矩阵。正文分析应优先使用测试集结果，验证集结果只用于说明模型选择过程，不作为主要性能结论。

## 6. 当前效果不稳定的根因判断

若训练日志出现训练损失接近 0、验证集 Macro-F1 明显高于测试集 Macro-F1 的情况，例如 `train_loss≈0.008`、`val_macro_f1≈0.82`、`test_macro_f1≈0.73`，应优先判断为数据划分和有效样本问题，而不是模型表达能力不足。原因是模型已经能够充分拟合训练集，说明其容量并不小；真正的问题在于模型从训练 segment/block 泛化到新的测试 segment/block 时出现性能下降。

因此，当前问题的主次关系应表述为：数据处理与实验划分协议是主因，模型复杂度是放大器。具体包括：第一，滑窗样本数量会高估真实独立样本数，因为相邻窗口高度重叠，真正独立的是 segment/block 级别样本；第二，少数类 group 数量少时，验证集可能只包含极少数少数类样本，导致验证 Macro-F1 对个别窗口非常敏感；第三，不同训练/测试比例若分别重新划分测试集，会把“训练数据减少”和“测试集难度变化”混在一起，可能出现训练比例更低但测试效果更好的反常现象；第四，当前 CAPT-UniShape 模型容量较大，会进一步放大对训练 group 的记忆。

后续修改应遵循以下顺序：先固定验证/测试协议并报告每个 split 的类别分布和 group 数量，再比较不同训练样本比例；然后对类别权重做 `none`、`sqrt_balanced` 和 `balanced` 的受控对照；最后才考虑模型结构简化或正则化。如果在固定测试集协议下仍出现明显 val-test gap，应优先采用多 seed 或 group-level 重复划分报告均值和标准差，而不是继续增加模型模块。
